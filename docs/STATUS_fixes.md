An independent read-only review of the diff found seven problems, all fixed:

- a stale assertion in the docker-gated `test_gym_docker.py`;
- `\uXXXX` decoded on the span but not on the logged text;
- word edges too strict: a date was not found inside an ISO timestamp, so letters and digits are now checked separately;
- a claim verified before the retry that was resent and failed could be both delivered and rejected (it now stays verified);
- a retry that withdrew every failed claim was labelled `accept` (now `fallback`, and withdrawn claims count as rejected);
- any later write excused a drifted read (now only writes that can change that state);
- `run_start.prompt_sha256` did not hash the prompt actually sent (a new `main_prompt` event does).

A second pass over the environment, budget and detector code found more, also fixed:

- The detector flagged ordinary words: `**Evaluation**` in an e-mail, `df["Evaluation"]`, and "ground truth" in prose. Each would have voided a correct run, so names now count only inside a filesystem search, and "ground truth" only in its path forms.
- Ground-truth data lines would have flagged a correct agent reading back its own output as *obtained*. Only grader code is fingerprinted now, and every file the seal keeps counts as readable.
- Pilot-era images carry the same tag. With `network_internal` they would have failed every run with `env_error`. A run with either isolation flag now refuses an image without the `evcarry.overlay=offline-v1` label, and the offline Docker tests skip on such an image.
- A DNS assertion contradicted its own comment about Docker engines before 26.0. It is removed; the connection checks remain.
- `evcarry summarize` now lists *obtained* calls. A note is printed when the reserve factor (1.6) is below the price table's worst component ratio (2.72).

Existing tests updated because the behaviour changed on purpose: the fault table (`test_mock_pipeline.py`: a fabricated entity and both false-action variants are now caught at L1, on every claim, instead of at a sampled L2), the judge truncation test, the re-delegation wording in `test_delegate.py`, the turn/ceiling assertions in `test_spend_limits.py`, and the SHA256SUMS line count.

## Projected headline cost: 60 tasks, OpenRouter only

Basis: the pilot's billed cost per finished run at its provider mix (92–94% InferenceNet; billed is 1.44× the same tokens at DeepInfra rates), the 60 headline tasks × 2 seeds × 4 arms = 480 runs, and the diagnosis' estimates for each fix. | **480 runs** | 58.5 | **56.4 (54.4–58.6)** | plus about $1 for the dev run |

**It does not fit $45.** At $56 the grid would also stop on the cap, not by design: with 8 runs in flight it reserves about $2.6, and the task-major grid would stop after about 45 of the 60 tasks.

Options that keep the 60 tasks, the 4 arms and both seeds (savings multiply; estimates):

| option | saving | fair across arms? | cost of the option |
| --- | --- | --- | --- |
| route to InferenceNet only (drop `deepinfra/fp8` from the set; still OpenRouter) | about −4%: no cache lost on provider switches (−7%), but the 6% DeepInfra calls get dearer | yes; it also removes the provider covariate | |
| 64k context instead of 131k (same block trim) | about −8% more (−12% in all at InferenceNet prices) | same rule in every arm | less context per call; verify success on the dev run |
| agents' reasoning at low effort (like the judge) | −8% to −20% (output is about 39% of billed cost; the reasoning share of agent output is not measured) | same setting on every agent call | a model-wide change: success rates can move, so it needs the dev run before the freeze |
| a per-call output cap (`max_tokens`, e.g. 8,192) | small; it only cuts runaway outputs | same in every arm | |
| a lower ceiling | large | **no**: it truncates the verifying arms most (biases H1) | not recommended |

- All three of the first options together: 56.4 × 0.96 × 0.92 × 0.86 ≈ **$43** (range about $40–46). That fits only at the central estimate, with little room for the reserve tail and the dev run.
- 64k plus low reasoning only: about $44.6.
- 64k plus InferenceNet only: about $49.8, which does not fit.
- The honest alternatives are a budget of about $60, or one seed first with seed 2 decided on measured cost (which drops the two-seed design unless the budget allows it).
- BYOK DeepInfra capacity would bring it to about $35, but it is out of scope for now.

**Arms.** The request said "keep 2 seeds and all 7 arms". The registered headline has 4 arms; 7 arms is the local M6 grid (`configs/experiments/local_core.yaml`). I kept 4. Seven arms on the 60 tasks × 2 seeds (840 runs) would cost about $105 at the same mix: typed ≈ vanilla, evidence-only ≈ $0.15, and evidence_random ≈ evidence_risk per run.
