# Code review: feat/gym-containers-l3-judge

Reviewed 2026-10-24 at commit `7610425` (PR #1's M0–M3 harness plus the gym containers and the L3 judge), against `CLAUDE.md` and `docs/plan/EXPERIMENT_PLAN.md`. Every file under `src/`, `configs/`, `prompts/`, `analysis/`, `docker/` and `tests/` was read. No paid API call was made, no model was loaded, and only containers this review started (labelled `evcarry.project=evidence-subagents`) were created and removed.

Baseline: `uv run pytest` gave 71 passed, 2 skipped. After the fixes below: 82 passed, 2 skipped (the two opt-in live-provider tests), including the nine Docker gym tests; no container or network was left over.

A Cursor agent session was editing the same working tree during the review (it added `openrouter_ds_1017` to `configs/models.yaml`, `configs/experiments/openrouter_smoke.yaml`, `configs/prices/openrouter_deepseek_1017_2026-10-24.yaml`, and an OpenRouter key in the gitignored `.env`). None of that is in these commits, and `.env` was not read.

Severity: **critical** invalidates paper results; **high** biases results, wastes paid runs, or breaks an arm on a real model; **medium** loses data or weakens a claim; **low** is hygiene.

## Verified on a real DeepSeek response (not possible here)

`token_usage_from_body` reads `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`; `served_identity` reads `body.model`. After the first smoke run, check that the second `llm_call` of a run has `cache_hit_tokens > 0` and that `served_model` differs from `deepseek-flash` when the alias routes. If thinking mode is on, check that multi-turn tool calls are accepted (some DeepSeek reasoning endpoints require `reasoning_content` to be sent back).

## What was checked and looks right

- Cost formula, peak windows (UTC, end exclusive, weekends off-peak) and the DeepSeek cache fields match the dated price table and the hand-computed tests.
- The judge sees only the claim and its cited calls (arguments, logged output, read-backs): no task text, no ground truth, no arm name. Its prompt is fixed and hashed into every `judge_call`.
- Writes are never replayed; read-backs come from `configs/gym_tools.yaml`; snowflake `read_query` refuses write SQL server-side.
- Docker isolation: one network, Postgres and agent container per run, labels per run, creates settle before teardown, removal is shielded and runs off the event loop. The full suite left nothing behind.
- API keys are read only from the environment and never passed into containers (only `DOCKER_*` reaches the docker CLI). No key is in git history.
- Prompts are byte-identical across runs of one arm (fixed workspace path, sorted tools).
